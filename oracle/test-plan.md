\# Oracle Website Validation Test Plan



\## Objective



Validate the quality of Oracle's public website through manual QA practices, focusing on functionality, localization behavior, accessibility considerations and release readiness.



The objective is to identify issues that could impact user experience across different markets and provide a documented release validation assessment.



\---



\# Scope



\## In Scope



\### Functional Validation



\- Verify pages load successfully

\- Validate navigation menus and internal user flows

\- Verify buttons, CTAs and interactive elements behavior

\- Validate internal and external links

\- Identify broken links or unexpected redirects



\### Content Validation



\- Verify content visibility and page structure

\- Validate missing components or layout issues

\- Verify images, documents and downloadable resources availability

\- Confirm localized content availability when applicable



\### Localization Validation



Validate available locales according to website availability:



\- English (EN)

\- Portuguese (BR)

\- Chinese (CN)

\- Japanese (JP)

\- German (DE)

\- Arabic (AR)



Validation points:



\- Locale availability

\- Localized content presence

\- Regional formatting:

&#x20; - Date formats

&#x20; - Number formats

&#x20; - Currency formats

\- Layout behavior with translated content

\- Locale-specific UI considerations



Note:

This validation focuses on localization implementation and consistency, not translation quality review.



\### Responsive Validation



Verify page behavior across different screen sizes:



\- Desktop resolution

\- 1024px viewport

\- 600px viewport



Validation points:



\- Content wrapping

\- Component alignment

\- Navigation behavior

\- Visual consistency



\### Accessibility Validation



Basic accessibility checks:



\- Alternative text availability for images

\- Keyboard navigation behavior

\- Heading structure

\- Color contrast considerations



\---



\## Out of Scope



The following items are not covered:



\- Backend validation

\- Performance testing

\- Security testing

\- Translation quality assessment

\- Database validation

\# Entry Criteria



Testing can begin when:



\- Website is publicly available

\- Pages are accessible without authentication

\- Target pages can be accessed successfully

\- Required locales are available for comparison



\---



\# Exit Criteria



Validation is considered complete when:



\- Planned test scenarios are executed

\- Issues are documented with evidence

\- Critical findings are reviewed

\- Localization concerns are identified

\- Release recommendation is provided
